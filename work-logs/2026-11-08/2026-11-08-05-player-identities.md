## 구현 내용

- 가상 이름 재료를 영어권 한글 발음·한국·일본으로 분리하고 기본 배분 60%/20%/20%로 생성한다. Paker 한 명은 김상혁으로 예외 지정한다. 이름은 표시 데이터이며 국적·인종 속성이나 능력 보정은 추가하지 않는다.
- 여러 종목 핸들에서 철자를 변형한 48종을 바탕으로 글자를 추가 변형한 후보를 만들고 중복 없이 뽑는다. 대소문자만 다른 닉네임도 중복 처리한다. 숫자 접미사는 붙이지 않으며 모든 닉네임은 영문자로 끝난다.
- 실제 영입 계약금이 가장 높은 선수 한 명을 Paker로 정한다. 동점이면 원래 목록에서 먼저 나온 선수를 선택한다. 능력과 가격·소속을 바꾸거나 자유계약으로 이동시키지 않는다.
- 이름 전용 난수를 사용하고 기존 생성 난수 소비량을 유지하여 시드별 능력·역할·소속 배정과 경기 난수에 영향을 주지 않는다.
- 세계의 선택적 `playerIdentityVersion: 2` 필드를 저장 v4에서 검증·보존한다. 필드 없는 기존 v2~v4 저장은 이름과 닉네임을 갱신한다. 이름 버전 1은 실명과 Paker 선수를 보존하고 닉네임만 갱신한다. 이름 버전 2는 다시 덮어쓰지 않는다. 저장 스키마 v1은 세계 생성 시 새 이름을 적용한다.
- 이어하기에서 갱신 사실과 미저장 상태를 표시한다. 읽기로 기존 저장 슬롯을 덮어쓰지 않고 명시적 구단 저장 시 반영한다. JSON 가져오기는 기존 확정/저장 흐름을 따른다.
