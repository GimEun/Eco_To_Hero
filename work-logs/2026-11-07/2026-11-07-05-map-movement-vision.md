## 구현 내용

- 벽·엄폐·통로·A/B 구역·시작점·목적지를 가진 중계소를 하나의 맵 데이터로 정의했다.
- DOM·Canvas와 독립된 기하 계산과 50ms 고정 단계 연습 상태를 구현했다. 기존 구단·선수 정보를 표시용 값으로 복사하고 경영·저장 상태는 변경하지 않는다.
- 4방향 BFS로 벽을 우회하고, 반지름 10의 선수 몸체가 벽·지도 밖을 통과하지 않도록 구간을 나눠 검사한다. 초기 테스트 속도는 초당 80 좌표 단위다.
- 전방 90도·거리 200의 광선 판정과 벽 모서리를 포함한 시야 다각형을 사용한다. 상대 중심점에 대해 시야·거리·벽 가림을 검사한다.
- 맵 연습 메뉴와 시작·일시정지·계속·초기화, 지도 클릭/선수 목록 선택, 시간·선택 선수 위치·감지 상대 표시를 제공한다. 양 팀 표시와 선택 선수의 감지는 안내·금색 표시로 구분한다.
- Canvas는 화면 크기·픽셀 배율에 맞춰 그리며 계산 좌표는 유지한다. 탭을 숨기면 일시정지하고 화면을 이탈하면 RAF·관찰자·이벤트를 정리한다.
- 모든 선수가 목적지에 도착하면 이동 테스트를 멈춘다. 사격·승패·선수 간 충돌·능력치 기반 이동·경기 저장은 포함하지 않는다.

## 주요 결정

- Canvas 2D 지도와 같은 격자 맵을 사용하는 충돌·경로·시야 계산을 분리하고 50ms 고정 단계로 진행한다.
  - 이유: 실제 상태 판정을 화면과 독립적으로 검증하고 프레임 빈도·창 크기가 계산 결과에 영향을 주지 않게 하는 승인된 설계다.
- 기존 세계에서 두 팀을 읽는 임시 연습 상태를 사용한다.
  - 이유: 경기 시스템을 단계적으로 검증하면서 구단·선수·저장 원본을 보존한다.

## 승인 범위

- 독자 맵 1개를 코드 데이터로 작성한다. 가칭 중계소, 24×16칸·칸당 40 좌표 단위의 지도에 벽·통로·엄폐·양 팀 시작점과 A/B 구역을 둔다. 사이트는 위치 표시만 제공한다.
- 같은 맵 데이터를 렌더링·경로 탐색·벽 충돌·시야 판정에서 사용한다. 사용자 제공 이미지가 없어 CSS·Canvas 도형을 사용한다.
- 기존 세계에서 내 팀과 같은 PC방 리그 AI 구단 1팀의 5명씩을 읽어 임시 연습 상태를 만든다. 구단·선수 원본과 저장 데이터는 수정하지 않는다.
- 경영 UI는 기존 HTML/CSS를 유지하고 경기 지도만 Canvas 2D로 표시한다. 추가 프레임워크·라이브러리는 도입하지 않는다.
- 계산은 DOM·Canvas에 의존하지 않는 고정 간격 50ms의 단계 진행으로, 화면은 requestAnimationFrame으로 분리한다. 화면 주사율·크기 변경이 경로·판정 결과를 바꾸지 않도록 한다. 이는 실제 경기 상태 검증을 위한 분리이며 범용 엔진 기반은 만들지 않는다.
- 선수는 팀별 색상 원형·번호로 표시하고 미리 정한 테스트 목적지까지 이동 가능 칸으로 경로를 계산해 이동한다. 벽·지도 밖 통과를 차단하며 시작·일시정지·초기화를 제공한다.
- 선택 선수의 시야를 전방 90도·거리 200 좌표 단위로 계산하고 벽 뒤는 가린다. 선수 선택과 시야 영역·시야 내 상대 표시로 판정 결과를 볼 수 있게 한다. 관전자는 양 팀을 볼 수 있으며 표시와 실제 선수 시야를 구분한다.
- 다음 단계의 사격·피해·사망·폭탄·경제·라운드·승패·수동 전술 편집·배속·경기 저장은 포함하지 않는다. 현재 화면은 경기 결과를 연출하는 장면이 아니라 이동·시야 검증용 연습 화면임을 명시한다.
