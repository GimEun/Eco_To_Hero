## 구현 내용

- 새 구단 생성 시 58팀·600명 세계를 구성하고 기존 5명도 전체 선수에 포함한다. 58팀에 5명씩 배정하고 310명은 자유계약이다.
- 플레이어 구단과 선수 원본은 세계 데이터 한 곳에서 관리하며 화면용 명단·소속은 ID 참조로 조회한다. 리그 정원·생성 범위는 config/world.js에 있다.
- 좌측 리그·구단 메뉴에서 리그별 팀을 선택해 명단을 확인하고, 전체 선수 메뉴에서 전체·자유계약·각 구단으로 필터링한다. 선수 목록은 30명씩 나누어 보여준다.
- 내 구단·타 구단·전체 선수 명단의 표 코드를 공통으로 사용한다. 가져온 구단명·선수 문자열은 HTML 이스케이프 또는 textContent로 표시한다.
- schemaVersion 2로 세계 전체를 저장·복원한다. v1은 정규화한 구단 내용으로 고정 시드를 계산해 결정적으로 변환한다. 이어하기 시 원본 저장을 바꾸지 않고 변환 미저장 안내를 제공하며 수동 저장으로 v2를 확정한다.
- 구형 JSON 가져오기도 기존 데이터 검증과 교체 확인 후 v2 세계로 자동 저장한다. 취소·검증 실패·쓰기 충돌 보호는 유지한다.
- 세계 검증에서 ID 유일성·존재하는 선수 참조·중복 소속 금지·구단별 5명·리그별 팀 수·전체 수·PC방 플레이어 구단을 검사한다. 저장소 DB 버전과 게임 스키마 버전을 구분해 DB 구조 변경 없이 지원한다.
- 기존 문서와 PROGRESS.md를 갱신했다. 추가 의존성·이미지·영입·경기·AI 경영 기능은 도입하지 않았다.

## 주요 결정

- 58팀×5명과 자유계약 310명, 승인된 리그별 임시 능력 분포로 초기 세계를 생성한다.
  - 이유: 사용자 승인 범위에서 전체 600명의 소속과 세계 규모를 검증 가능하게 구성한다.
- 선수 원본 한 곳과 구단별 선수 ID 참조를 사용하며, 저장 v2에 세계를 포함하고 v1 구단을 보존해 변환한다.
  - 이유: 소속·명단 중복을 피하면서 기존 구단을 유지하고 새로고침 후 동일한 세계를 복원한다.

## 승인 범위

- 플레이어 구단을 포함한 58팀을 PC방 8·시 10·도 12·전국 12·전세계 16팀으로 배정한다.
- 전체 가상 선수 600명 중 구단별 5명씩 290명을 소속시키고 나머지 310명은 자유계약 선수로 둔다. 플레이어의 기존 5명도 600명에 포함한다.
- 선수 필드는 현재의 이름·별명·포지션·에임·지능·체력을 기본으로 한다. 나이·잠재력·등급 산식·훈련·계약 효과는 이번에 확정하거나 구현하지 않는다.
- 생성 선수의 기본 능력은 PC방 30~54, 시 40~64, 도 50~74, 전국 60~84, 전세계 70~94, 자유계약 20~89 범위를 추천한다. 이는 첫 세계 생성용 임시 분포이며 경기 밸런스 확정이 아니다. 기존 플레이어 선수는 원래 능력을 보존한다.
- 세계에 난수 시드를 기록해 같은 시드로 같은 초기 데이터를 생성한다. ID·소속·리그 배정을 검증한다.
- 리그/구단 목록·선택 구단 선수 명단·전체 선수 목록과 소속 필터를 추가한다. 자유계약 선수는 조회만 제공하며 영입·계약은 포함하지 않는다.
- 구단은 선수 ID를 참조하고 선수 원본은 세계 목록 한 곳에서 관리한다. 현재 선수 중복을 피하고 600명을 단일 소속으로 연결하기 위한 구체적인 변경이다. 범용 엔진·플러그인 계층은 도입하지 않는다.
- 세계 데이터를 포함하는 저장 스키마 v2를 추가한다. v1 저장·백업은 기존 구단명·자금·선수 5명을 보존해 불러온다. 불러오기 시 변환된 세계는 메모리에서 구성하고 사용자가 저장하기 전에는 기존 IndexedDB 레코드를 덮어쓰지 않는다. JSON 가져오기는 기존의 검증·교체 확인 후 저장 정책을 유지한다.
- 전체 경기·리그 일정·순위·승강·훈련·시장 거래·AI 경영 행동은 제외한다.
