# 개발 계획과 첫 구현 승인안

- 상태: 과거 단계별 계획·결정 이력을 보관한다. 최신 구현/확인 대기·재개 지점·미구현 순서는 [PROGRESS.md의 현재 진행 중인 작업](../PROGRESS.md#현재-진행-중인-작업)을 따른다. 시즌 1단계·설명/표·AI 후속은 구현 후 확인 대기이며, 다음 미구현 기능은 PC방 시즌 2단계 공식 경기 연결이다.

## 이번 작업의 경계

2026-11-09 사용자 지정으로 경기 AI 후속 3건보다 로고 에셋 적용을 먼저 진행한다. 창단 시 제공 로고 60개(S/C 포함) 중 선택·타 구단 무작위 배정·내 구단 제목/팀 연습 점수판·기존 저장 호환을 연결했다. 다른 에셋과 AI 개선은 별도 후속 범위이며 검증/사용자 확인은 [로고 작업 기록](../work-logs/2026-11-09/2026-11-09-03-club-logos.md)을 따른다.

초기 환경 확인·경쟁 게임 조사·설계 문서 4개 작성은 [조사 작업 기록](../work-logs/2026-11-07/2026-11-07-01-project-kickoff.md)에서 사용자 승인으로 완료했다. CPL 온보딩 해금과 Gladi 5인 영입이 필요한 기능은 미검증으로 기록했다. 승인된 첫 구현은 [별도 작업 기록](../work-logs/2026-11-07/2026-11-07-02-first-game-flow.md)에서 구현·검증·사용자 확인까지 관리한다.

## 작은 단계별 로드맵

**최신 관리 규칙(2026-11-10):** 최신 인수인계와 실행 순서는 별도 파일 없이 [PROGRESS.md의 현재 진행 중인 작업](../PROGRESS.md#현재-진행-중인-작업)에서만 관리한다. 아래의 과거 11개 목록과 우선순위 변경 기록은 당시 이력이다. 구현 후 확인 대기는 미구현 작업 번호에서 분리했으며, 현행 미구현 순서는 공식 경기 연결 → 주간 진행/시즌 종료 → 공식 보상/스폰서 → 플레이오프 → 승강/상위 리그 → 선수 생애다. 표 외 추가 화면 배치 범위는 미정 사항으로 보존한다.

**추가 우선순위 변경(2026-11-09):** 사용자 요청으로 설명 텍스트 정리·내용별 ‘설명’ 버튼·별도 설명창을 새 1번에 추가한다. 설명은 글자 크기·문단·간격을 정리하고 해당 내용에 맞게 제공한다. 기존 화면 가시성·한 화면 배치 개선은 2번으로 이동하며 나머지 상대 순서는 유지한다. 최신 남은 작업은 총 11개이며 [PROGRESS의 순서](../PROGRESS.md#남은-작업-실행-순서)가 아래 과거 안내보다 우선한다.

**최신 실행 순서·완료 승인(2026-11-09):** 사용자가 지금까지 구현한 작업을 일괄 완료 승인했다. 남은 작업 1번은 완성된 선수 능력·경험치 표를 참고한 기존 화면의 가시성·한 화면 배치 개선이다. 이어서 설치/해체 판단 → 장비 보존 → 사이트 전환/팀 간격 → 나머지 에셋 → PC방 정규 시즌 → 공식 보상/스폰서 연동 → 플레이오프 → 승강/오프시즌/상위 리그 → 선수 생애 순서다. 범위와 최신 상태는 [PROGRESS의 남은 작업](../PROGRESS.md#남은-작업-실행-순서)을 따른다. 아래의 과거 우선순위와 확인 대기 표현보다 이 안내를 우선하며, 공식 시즌 의존 기능과 아직 구현하지 않은 AI 개선은 완료에 포함하지 않는다.

최신 실행 순서(2026-11-08 사용자 지정): 기존 남은 목록의 **4 → 5 → 6 → 1 → 2 → 3** 순서로 진행한다. 구단 경영 확장 → 투자/재정 위기 → 경기/에셋 확장 → PC방 정규 시즌 → 플레이오프/승강/오프시즌·상위 리그 → 선수 생애/유스다. 아래 기존 단계 번호는 기능 분류로 유지하며 실행 우선순위를 뜻하지 않는다. 시즌에 의존하는 상금 지급 등은 시즌 연결 시 완성하고, 우선 시즌 없이 동작하는 경영 기능부터 나눠 구현한다.

최신 범위 결정(2026-11-08): 사용자 요청으로 스카우팅, 이적 협상 확장(역제안·확률 협상·AI 선제 제안), AI 자율 운영 확장을 개발 계획에서 제외한다. 기존 영입·자동 판매·거래에 따른 AI 명단 정리는 유지한다. 아래 과거 우선순위와 작업 기록의 해당 기능 후속 안내보다 이 결정을 우선한다.

## 첫 구현 단계 상세 제안

추천 기술은 기존 Node.js·JavaScript·HTML·CSS 유지와 Vite 개발 의존성 추가다. 이유는 기존 규칙에 맞추면서 개발 서버와 빌드 확인을 표준 도구로 제공하기 때문이다. React·TypeScript·Phaser는 첫 단계에서 도입하지 않는 안이다. [기술 설계](TECHNICAL_DESIGN.md)의 장기 구조는 후속 단계 제안으로 남긴다.

첫 단계는 다음만 구현한다.

1. package.json·lockfile·실행 진입점·개발/빌드 명령.
2. ECO TO HERO 가제를 설정 한 곳에서 바꿀 수 있는 메인 메뉴.
3. 새 게임 시작 화면: 전술형 FPS만 시작 가능, 다른 종목은 준비 중 안내.
4. 가상 구단 생성: 구단명 입력·빈 값 검증·생성·취소.
5. 초기 구단 정보: 입력한 구단명, PC방 리그, 운영 자금 $15,000.
6. 가상 임시 선수 5명의 이름·에임·지능·체력·포지션 표시.

기본 명단 무상 지급, 임시 선수 5명, 구단명만 입력하는 범위는 사용자 승인 후 구현했다. 계약·급여·등급 산식·영입 비용을 확정한 것은 아니다. 새로고침하면 초기화되는 메모리 상태만 제공한다. 저장·전체 600명·AI 구단·리그 일정·경기·이미지 생성은 첫 구현에 포함하지 않는다.

## 첫 단계 사용자 확인 기준

- 메뉴 → 새 게임 → 구단 생성 → 초기 정보로 이동한다.
- 빈 구단명을 제출하면 안내하고 생성하지 않는다. 취소하면 이전 화면으로 돌아간다.
- 정상 생성 후 구단명·PC방 리그·$15,000·가상 선수 5명과 1~99 능력치가 표시된다.
- 준비 중 종목은 시작되지 않는다. 저장을 지원하는 것처럼 표시하지 않는다.
- 다크 네이비·차콜·파랑·보라 UI가 읽기 편하며 에셋 없이 이용할 수 있다.
- AI 빌드·정적 검토 후 사용자가 앱을 실행해 위 흐름을 확인한다. 실제 명령·주소는 구현 시 안내한다.
